☁️ Arquitectura BYOC y Protocolo de Sincronización E2EE

PCMPrivateClipManager opera bajo el principio estricto de Zero-Knowledge Encryption. El sistema no depende de intermediarios, APIs propietarias ni servidores de terceros. Los datos se empaquetan y cifran localmente con el algoritmo militar AES-256 mediante pyzipper, permitiendo que utilices cualquier proveedor de almacenamiento como canal de transporte seguro.

🛡️ Protocolo y Reglas de Oro de Sincronización:

  • Protección Anti-Atraso (Blind Overwrite Prevention): Si tu equipo detecta que en la nube existe una versión más reciente (ej. Revisión #12 vs Local #10), el botón de subida se inhabilitará automáticamente. Esto impide que cambios desactualizados sobreescriban el trabajo nuevo. Siempre debes descargar primero.
  • Control de Reseteo a Revisión #0: El contador de revisiones no puede reiniciarse a voluntad mientras la nube contenga una bóveda activa, ya que rompería la cadena cronológica de tus otros equipos. La opción de editar o resetear a #0 solo se desbloquea si la carpeta de la nube se encuentra limpia y vacía.
  • Protocolo de Rotación de Llaves (N + 1): Al regenerar una clave de cifrado, la bóveda anterior es purgada y el nuevo paquete se compila con la revisión inmediatamente siguiente ($N + 1$). Esto garantiza que todos tus nodos reconozcan el cambio y soliciten la nueva clave antes de sincronizar.
  • Extracción Atómica y Verificación SHA-256: Antes de reemplazar tu base de datos local (pcm.db), el sistema valida la firma criptográfica SHA-256 estipulada en pcm_vault.meta. Si la descarga estuviera incompleta o la clave fuera errónea, la operación se aborta sin alterar tus datos existentes.

⚠️ Confirmar Rotación de Llave

Se generará una nueva clave aleatoria de 256 bits con máxima entropía.

Al guardar cambios:

  1. La bóveda anterior en la nube se eliminará de forma segura.
  2. Se compilará una nueva bóveda re-cifrada con esta nueva llave.
  3. Deberás copiar la nueva clave en tu notebook para mantener la sincronización.
